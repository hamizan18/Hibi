## Limitations

Database, habit/finance occurrence and transaction records, lifecycle/resolution reasons, recovery notes and audit snapshots are unencrypted; private-view access control and privacy deletion are not implemented (Milestone 6). The initial-start action pauses rather than permanently cancels a habit. Future version scheduling UI, read-only audit inspection and History & Analytics evaluation are implemented for all eight tracking types, while backdated target/log correction UI is currently implemented for counter habits only. Multiple unlinked legacy counter-correction audit chains cannot be safely ordered and remain explicit `conflict` records. While in-place `v12 -> v14` migration, cold launch, 5-tab navigation, and Finance/Growth visual layout were verified on a physical Android 16 device (`2510DRA23E`), there is still no `integration_test/` suite, and on-device timezone-change and interactive Finance CRUD/restart walkthroughs were intentionally left for the owner so no fake records are written into their live database. Missing historical recovery metadata remains ineligible. Low-level recovery writers do not enforce all UI eligibility checks; callers must use the guarded eligibility services. Current duration timers exist only in screen state and may be lost on navigation, background/resume, visibility changes or midnight (Milestone 4). Raw SQL can bypass application-level checks, including non-counter lifecycle occurrence protection. No release signing or final application ID has been configured (Milestone 7).

Immutable lifecycle, start-pause, resolution, recovery, checklist, avoidance, typed-log, correction-audit and finance-audit triggers still require an explicit future privacy-deletion design in Milestone 6.
