# Security and privacy

## Threat model and current limitation

Hibi is offline and single-user; sensitive data must never be sent to external services. Device theft, unlocked-device access, backups, notification previews, exported files, logs and recent-app previews can disclose data. The foundation's SQLite database is **not encrypted at rest**. Android device protections are not a guarantee against a compromised or unlocked device. App lock, when built, is not database encryption. Do not represent planned safeguards as operational.

The local `habit_version_audit` table stores habit names, target units, counts and schedule details in unencrypted snapshots; `habit_counter_event_audit` stores occurrence IDs, progress quantities and timestamps. Counter resolution records, counter recovery records and lifecycle events may contain optional user-provided reasons or notes and target/progress snapshots. They are not tamper-proof, have no private-view access controls or privacy deletion workflow yet, and are not exposed in the UI. Those controls must be implemented before a privacy milestone can be accepted.

Non-counter creation snapshots also contain version metadata, schedules, checklist labels or typed targets and lifecycle details. They are stored in the same unencrypted local audit table and require the same future privacy controls and deletion handling.

## Milestone 6 implemented privacy controls and honest boundaries

- **App Lock (`AppLockService`, `AppLockGate`)**: optional local 4–12 digit PIN verified via vetted `PBKDF2-HMAC-SHA256` (100,000 iterations, random 128-bit salt, constant-time comparison) stored in Android Keystore via `flutter_secure_storage` (never plaintext, never in SQLite, never exported in backups). Supports exponential backoff after 5 wrong attempts, optional Android `BiometricPrompt` via `local_auth` (`FlutterFragmentActivity`), lock on launch and resume, and Android `FLAG_SECURE` recent-app preview protection (`MainActivity.kt`). Forgotten-PIN recovery has no backdoor or cloud account; it requires typing `ERASE ALL LOCAL DATA` to wipe all local data before clearing the PIN verifier.
- **Database encryption evaluation (honest status)**: `hibi.sqlite` remains **unencrypted at rest** on disk. App Lock protects ordinary unlocked-device UI access only and is explicitly documented as NOT database encryption at rest. Full SQLCipher at-rest database encryption remains a deliberate architectural trade-off (requiring native SQLCipher packaging and migration tooling) and is not claimed as active.
- **Permanent Privacy Deletion (`PrivacyDeletionService`)**: supports explicit-phrase-confirmed permanent deletion of a habit (removing all versions, occurrences, events, resolutions, recoveries, immutable audit rows, reminders, goal links and XP ledger entries while atomically recreating all SQLite triggers) and permanent deletion of private journal entries, recording only sanitized non-sensitive summaries in `backup_history`.
- **Safe Local Reminders (`ReminderService`)**: private and unclassified habits emit generic notification text (`Hibi check-in`) by default unless `allow_sensitive_text` is explicitly enabled; paused/archived/deleted/unscheduled habits cancel/skip alerts; falls back to Android `inexactAllowWhileIdle` when exact alarms are unavailable and never guarantees delivery under OEM Doze/battery restrictions.
- **Encrypted Backups & Private-by-Default Exports (`BackupRestoreService`, `ExportService`)**: backups are encrypted by default using vetted `PBKDF2-HMAC-SHA256` + `AES-GCM-256` + SHA-256 integrity digest, exclude all PIN/biometric credentials, validate format/schema/checksum/foreign-keys before atomic full replacement, and produce a recoverable encrypted pre-restore snapshot. Human-readable JSON, CSV and PDF exports exclude private habits, journals and goals by default (`includePrivate = false`) and carry an explicit unencrypted-file warning.
